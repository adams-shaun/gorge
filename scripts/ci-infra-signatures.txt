# ci-infra-signatures.txt: the infrastructure faults after which scripts/ci-infra-retry.sh runs a CI step once more.
# One row per fault, name<TAB>ERE, matched against each line of the step's log; the first row that matches names
# the fault. A log with a test verdict never retries, whatever it matches here. A lost runner or an empty log cannot be
# retried from inside a step (the job itself is gone), so neither is a row.
killed	signal: killed|exit code 137|fatal error: runtime: out of memory
no-space	[Nn]o space left on device
network	fatal: unable to access 'https://github\.com/|RPC failed; HTTP 5[0-9][0-9]|TLS handshake timeout|dial tcp [^ ]+: i/o timeout
# A test binary that breaches its own -timeout panics with this line and prints no --- FAIL, so it is not a verdict.
# Matched only at fresh-clone-check.sh's `-timeout 5m` (job lint), the one place CI runs a package at 5m: the test
# shards use -timeout 20m, and retrying a genuine 20m hang would add 20m to a batch. A --- FAIL assertion anywhere in
# the same log still forbids the retry (verdict runs before signature).
test-timeout	panic: test timed out after 5m0s
