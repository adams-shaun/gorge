# The wire protocol (`server/protocol`)

[`server/protocol`](https://pkg.go.dev/github.com/adams-shaun/gorge/server/protocol) is the
versioned wire between a match host and its clients. It has one envelope (`Frame`), a closed
set of frame types, and plain JSON bodies. The HTTP API returns these bodies, and the
[event stream](sse.md) carries them as frames. This page covers the envelope, every frame type
with its body, the vocabularies the bodies use, the versioning rule, and the tests that pin
the wire. It is for client authors in any language who want to decode frames without reading
Go.

!!! note "Why a separate package"
    `server/protocol` is types only. It never imports the rules engine or the bot packages
    (`internal/archtest` forbids `server/protocol → engine/rules` and `server/protocol → bots`).
    A client library can therefore depend on it without pulling in the engine. The board
    projection a frame carries, `view.View`, comes from `engine/view`. That package is also
    barred from importing `engine/rules`.

field optional; a nil pointer, slice or map in a non-`omitempty` field is `null`.

## The envelope

```json
{
  "v": 1,
  "t": "decision",
  "id": 4182,
  "table": "t1",
  "match": 7,
  "seq": 9131,
  "body": {"player": 2, "kind": "priority", "prompt": "You have priority."}
}
```

*(`testdata/decision.json`, the golden.)*

| Field | Type | Meaning |
|---|---|---|
| `v` | int | `protocol.Version`, currently **1** |
| `t` | string | The frame type, which selects the body |
| `id` | uint64, optional | The session-wide frame counter and the SSE id. Omitted (0) on frames that cannot be resumed: `hello`, `widget` and `overflow`. |
| `table` | string, optional | The table the frame is about |
| `match` | int, optional | The match index on that table, from 1 |
| `seq` | uint64 | The engine's event sequence the body is located at: the number the match's hash chain covers |
| `body` | object | The frame type's body, below |

### Events on the wire

An `EventBody` carries one engine event (`protocol.Event`) and its English transcript `line`:

```json
{"event": {"seq": 9131, "kind": "move_zone", "player": 1, "obj": 12, "from": "hand", "to": "battlefield"},
 "line": "Goblin Guide #12 moves from hand to battlefield"}
```

Zone names (`from`, `to`) are set only for `move_zone`, `draw` and `stack_push`, and `step`
only for `step`. A `tap` therefore never reads as "from library". `secret` marks an event
whose hidden payload was redacted for this viewer: a draw you may not see keeps its shape and
loses its card. Events are redacted against the state at the head of the request, for the
viewer's visibility, before the line is described. A hidden card's name never reaches the
line.

`kind` is the name of an `events.Kind`. That enum is **append-only**: new kinds are added at
the end, so existing ordinals never move. Recorded logs, hash chains and golden replays depend
on them. A client must treat an unknown kind as displayable but opaque, and use
`line`.

## Versioning

The rule is the doc comment on `protocol.Version`:

> Version bumps only on a breaking change to a frame body. Additive fields do not bump it.

What this means in practice, and how firmly each part is held:

| Promise | Held by |
|---|---|
| Every frame carries `v`, and it is 1 today | `NewFrame` always stamps `Version`; `TestFramesRoundTrip` checks it |
| A field's name, type and presence do not change silently | `TestGoldens` (byte-identical goldens), `TestCommittedProtocolTSIsFresh` and `TestOpenAPISchemasMatchGo`. Each of them fails on any change, additive or not, until its committed artifact is regenerated, so every wire change is a visible diff in review. |
| The frame-type set and the decision-kind set are closed | `TestFrameTypeUnionListsEveryConstant`, and the `Kind` check in `TestOpenAPISchemasMatchGo` |
| A **breaking** change bumps `v` | A convention, stated in the doc comment. No test can tell a breaking change from an additive one, so the bump is a reviewer's call. |
| New fields are **additive** and may appear at any time | The convention above. Clients must ignore unknown fields. Fields added so far are mostly `omitempty`, so payloads that do not use them serialise byte-identically. |

There is no negotiation: a server speaks one version, and URLs carry none. A client should read
`v` and refuse a version it does not know.
